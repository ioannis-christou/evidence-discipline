# PROCESS — errors in how the work was run, and the rules that replaced them

Method errors are cheap to find, because a control catches them. Process errors
are expensive, because nothing catches them except noticing. These five cost
real time. Each is recorded with the rule it produced.

Written mid-programme, not in hindsight, and applied from that point on.

---

## 1. Stop presenting either/or when both can run

Happened twice in a single day. First as "A or B" — two options that turned out
to be two columns of one table, where building both was cheaper than building
either. Then as "collect more data or investigate the anomaly" — collection is
bounded by network wall-clock, investigation is analysis, and they compete for
nothing.

**Rule:** before offering a choice, check whether the two options consume the
same resource. If they do not, start both and say so.

## 2. Do not stay in one venue

Days went into going deeper into a single venue — census, replay, timing — while
the rest of the market went untouched. Depth felt like progress, because every
step produced a real measurement. It was still one venue, and the venue turned
out to be closed.

**Rule:** when a line of work produces three consecutive negative results, the
next action is a different subject, not a fourth measurement in the same one.

## 3. Use the instrument at the scale it was built for

The grader was built with a multiple-comparison correction specifically so that
thousands of hypotheses could be tested honestly. It was then run 72 times. The
first wide run — 888 hypotheses — immediately showed a coherent pattern that 72
could not have shown.

**Rule:** if the tool corrects for N trials, run N trials.

## 4. Test collectively before concluding

Twelve markets were each tested alone, produced 5–7 out-of-sample observations
each, and were dismissed for small samples. Pooling the same rule across all
twelve gave 708 observations and a completely different picture.

**Rule:** the rule is the hypothesis; a market is a sample of it. Pool first.

## 5. Measurement must terminate in a decision

Every result was reported as a measurement, and the question *so what follows
from this* was deferred to a next step that kept moving.

**Rule:** every report names the decision it supports, or says plainly that
nothing followed from this direction, so the direction closes.

---

## What was not a mistake, recorded so it is not over-corrected

The controls stay.

They killed a +7.0% result that rested on one lucky case, and a +11.89%
expectancy that replayed an entry nobody could have reached. Removing them would
produce numbers faster and produce wrong numbers faster.

The failure was never that the measurements were too careful. It was that they
were too narrow, and did not end in a decision.
